# NHTSA Complaint Classification: Zero-Shot LLM vs. Fine-Tuned Encoder vs. Fine-Tuned LLM

Given a raw [NHTSA vehicle complaint](https://www.nhtsa.gov/nhtsa-datasets-and-apis) narrative
(free text) plus structured metadata (make/model/year), predict the affected vehicle
**component** (40 categories) and secondary flags (`CRASH`, `FIRE`, `INJURED`, `DEATHS`).

The interesting part isn't the classification task itself — it's the three-way comparison
built around it, designed to answer a concrete question: **when you fine-tune a model on
labels distilled from a frontier LLM, how much of that LLM's accuracy do you actually get
to keep, and does it matter whether the fine-tuned model is a small encoder or a small
generative LLM?**

**Read [`WRITEUP.md`](WRITEUP.md) for the full writeup** — methodology, every metric,
error analysis, and the reasoning behind each decision along the way. This README is a
short map of the repo and how to reproduce each stage.

## The three rungs

| Rung | Approach | Gold accuracy (n=551) | Macro-F1 | Cost to run 100K rows |
|---|---|---|---|---|
| 1 | Frontier LLM, zero/few-shot (Claude Sonnet) — the teacher | 86.6% | 0.764 | ~$467 (on-demand) / ~$233 (batch) |
| 1 | Frontier LLM, zero/few-shot (Claude Haiku) — cheap tier | 85.1% | 0.752 | ~$154 |
| 2 | Fine-tuned encoder classifier (DeBERTa-v3-base, 40-class head) | 82.2% | 0.775 | ~$0 marginal, CPU-only |
| 3 | Fine-tuned open-weight LLM (Qwen2.5-7B-Instruct + LoRA), trained on the teacher's labels | **86.2%** | **0.799** | ~$0 marginal if self-hosted; GPU needed for latency |

The fine-tuned 7B LLM (Rung 3), distilled entirely from the teacher's own labels,
lands within half a point of the teacher it was trained on and clearly ahead of the
fine-tuned encoder (Rung 2) on every metric — at effectively zero marginal
inference cost once trained. See `WRITEUP.md` §7 for the full cost/latency/deployment
breakdown, and §3.3 for a skeptical read on what that ~87% actually means (the teacher
isn't a perfect oracle; several of its "errors" are genuinely ambiguous complaints).

## Repo layout

```
scripts/            All pipeline code — data prep, labeling, training, evaluation
output/             Eval results, gold sets, label schema, run summaries (JSON)
data/               Training data (parquet) — regenerated by scripts, not fully versioned
checkpoints/        Trained model configs/adapters (weight binaries gitignored — see below)
PROJECT_PLAN.md     Original plan/rationale for the three-rung comparison
WRITEUP.md          Full writeup: methodology, results, error analysis, decision log
```

### Pipeline, in order

1. **Data prep** — `scripts/load_data.py` (raw NHTSA flat file → parquet) →
   `scripts/prepare_training_data.py` (clean, scope to `PROD_TYPE='V'`, dedupe).
2. **Label schema + gold set** — `scripts/schema.py`, `output/label_schema.json`,
   `output/NHTSA_CODING_GOTCHAS.md`. Gold eval set built/expanded via
   `scripts/build_gold_eval_set*.py` and `scripts/build_rare_gold_expansion.py`
   (see `WRITEUP.md` §3.4 for the rare-category coverage expansion methodology).
3. **Rung 1 teacher labeling** — `scripts/teacher_prompt.py` (prompt/schema definitions)
   + `scripts/run_batch_cascade_labeling.py` (Haiku→Sonnet confidence-cascade batch
   labeling of the full training set, ~62K + a targeted rare-category top-up via
   `scripts/build_training_sample_rare_topup.py`). Cost modeling in `scripts/pricing.py`
   and `scripts/analyze_confidence_cascade.py`.
4. **Rung 1 eval** — `scripts/eval_models_on_gold.py` scores any zero-shot LLM
   against the gold set.
5. **Rung 2 training** — `scripts/train_deberta.py` (DeBERTa-v3-base fine-tune, GPU
   recommended). Eval a saved checkpoint with `scripts/eval_checkpoint_deberta.py`.
6. **Rung 3 training** — `scripts/train_llm_lora.py` (Qwen2.5-7B-Instruct + LoRA/QLoRA
   fine-tune, GPU required). Eval a saved checkpoint with
   `scripts/eval_checkpoint_llm.py`.
7. **Novel-category flexibility probe** — `scripts/novel_category_probe.py` (shared
   synthetic narratives) checks whether either fine-tuned model still generalizes to
   categories it saw little/no training data for — see `WRITEUP.md` §5.5.

Every script that hits an LLM API or trains on GPU was run against a **held-out gold
set** the model never saw in training, adjudicated by hand against the class
definitions in `scripts/teacher_prompt.py` (not just NHTSA's raw, noisy `COMPDESC`
field — see `WRITEUP.md` §3.3-3.4 for how much that adjudication actually changes).

## Reproducing

```bash
pip install -r requirements.txt
cp .env.example .env   # fill in ANTHROPIC_API_KEY / OPENAI_API_KEY as needed
python scripts/load_data.py
python scripts/prepare_training_data.py
# ... see WRITEUP.md for the full sequence + expected runtimes/costs at each stage
```

Rung 2 trains in a few hours on a single L4-class GPU; Rung 3 takes roughly a day on
an H100 (or longer on smaller cards) — see `WRITEUP.md` §5.2 for the runtime breakdown
and the prompt-shortening optimization that got it there.

### On model weights

`checkpoints/` tracks each trained run's small config/tokenizer/adapter-config/README
files (so the exact hyperparameters of every run are visible in the repo) but not the
multi-hundred-MB weight binaries themselves (`*.safetensors`, `*.bin`) — those are
regenerated by re-running the training scripts above against a rented GPU.
